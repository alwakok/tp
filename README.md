# АИС «Техподдержка»

Веб-приложение service desk на Flask: регистрация заявок, назначение
исполнителей, комментарии, вложения, отчёты и ролевая модель доступа.

## Стек

- Python 3.11+
- Flask 3.1, Flask-SQLAlchemy, Flask-Login, Flask-WTF, Flask-Limiter
- Flask-Migrate (Alembic) — миграции схемы
- SQLite (по умолчанию; меняется через `DATABASE_URL`)
- Сервер отрисовывает HTML сам (Jinja2), клиентского JS в проекте нет

## Роли

| Роль | Доступ |
|---|---|
| `requester` (заявитель) | создаёт заявки, видит и комментирует только свои |
| `operator` (оператор) | видит все заявки, назначает исполнителей, меняет статус |
| `executor` (исполнитель) | видит и ведёт только назначенные ему заявки |
| `manager` (руководитель) | видит все заявки и отчёты, только просмотр (не может менять заявки) |
| `admin` (администратор) | полный доступ, управление пользователями и справочниками |

## Установка

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

MIME-проверка загружаемых файлов использует `python-magic`, которому на
Linux нужна системная библиотека `libmagic`:

```bash
# Debian/Ubuntu
sudo apt install libmagic1
```

Для разработки и прогона тестов дополнительно:

```bash
pip install -r requirements-dev.txt
```

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `SECRET_KEY` | — (обязателен в проде) | ключ подписи сессий/CSRF. В dev генерируется временный при старте |
| `FLASK_ENV` | `development` | `production` включает обязательный `SECRET_KEY` и `SESSION_COOKIE_SECURE` |
| `FLASK_DEBUG` | `0` | `1` включает debug-режим dev-сервера — **никогда не включайте в проде** |
| `DATABASE_URL` | `sqlite:///tech_support.db` | строка подключения SQLAlchemy |
| `SESSION_COOKIE_SECURE` | авто (см. `FLASK_ENV`) | принудительно `1`/`0`, если нужно переопределить |
| `SEED_DEMO_DATA` | `1` | `0` отключает автосоздание демо-пользователей и категорий при первом запуске |
| `BEHIND_PROXY` | `0` | `1`, если приложение стоит за Nginx/другим обратным прокси — включает `ProxyFix`, чтобы rate limiter и audit-лог видели реальный IP клиента, а не IP прокси |

## Запуск (разработка)

```bash
python app.py
```

Приложение поднимется на `http://localhost:5001`. При первом запуске
(`SEED_DEMO_DATA=1`, по умолчанию) создаются демо-пользователи:

| Логин | Пароль | Роль |
|---|---|---|
| admin | 12345678 | Администратор |
| operator1 | 12345678 | Оператор |
| executor1 | 12345678 | Исполнитель |
| manager1 | 12345678 | Руководитель |
| user1 | 12345678 | Заявитель |

**Смените эти пароли перед реальной эксплуатацией** и установите
`SEED_DEMO_DATA=0` на проде, чтобы такие учётки вообще не создавались.

## Миграции схемы

Для первого разворачивания схемы достаточно `db.create_all()` (вызывается
автоматически при старте). Но он создаёт только отсутствующие таблицы и не
умеет накатывать изменения на существующие — любое последующее изменение
`models.py` нужно вести через Alembic/Flask-Migrate:

```bash
export FLASK_APP=app.py

# применить все миграции (включая начальную схему из migrations/versions/)
flask db upgrade

# после правки models.py — сгенерировать новую миграцию
flask db migrate -m "описание изменения"
flask db upgrade
```

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Покрыто: логин (успех/неверный пароль/несуществующий логин/заблокированная
учётка), защита от open redirect на `/login?next=`, регистрация (роль
всегда `requester`), RBAC по ключевым эндпоинтам (`/admin/*`, `/tickets/reports`),
IDOR-защита карточки заявки (чужая/неназначенная заявка — 403), защита
CSV-экспорта от formula injection, уникальность номера заявки.

## Структура проекта

```
app.py          — фабрика приложения, error-handlers, демо-данные
auth.py         — логин/регистрация/logout, rate limiting, RBAC-декоратор
admin.py        — управление пользователями и категориями (только admin)
tickets.py      — заявки: CRUD, вложения, комментарии, отчёты
audit.py        — журнал действий (audit_logs), используется всеми блупринтами
models.py       — модели SQLAlchemy
forms.py        — формы WTForms с валидацией
config.py       — конфигурация приложения
migrations/     — миграции схемы (Alembic/Flask-Migrate)
templates/      — Jinja2-шаблоны
static/         — CSS (клиентского JS в проекте нет)
tests/          — pytest-тесты
```

## Известные ограничения

- Rate limiter и `flask-login`-сессии хранятся в памяти процесса — при
  нескольких воркерах (gunicorn и т.п.) состояние не шарится между ними.
  Для прод-многопроцессного деплоя лимитеру нужен внешний storage (Redis и т.п.).
- Нет функций смены/восстановления пароля пользователем — только
  администратор может создавать учётки и (раз)блокировать их.
